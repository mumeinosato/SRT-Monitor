# 送信側(OBS Studio)の設定

まっさらな OBS Studio から、srtrx(受信機)へ映像を送るまでの手順。
**Raspberry Pi 3B+ を受信機にして、実機で確かめた値**(2026-11-16、OBS Studio 32.1.2、Windows、日本語表示)。
受信機が x86 の PC なら、解像度とビットレートは上げてよい([「受信機が Pi 3 でないとき」](#受信機が-pi-3-でないとき))。

表記: **設定 → 配信** は、OBS 右下の「設定」ボタンを開き、左のリストの「配信」を選ぶ、の意味。

## 0. 先に決めておくもの

| 項目 | この文書での例 | 備考 |
| --- | --- | --- |
| 受信機のアドレス | `192.168.20.15` | 受信機(Pi)の IP。固定にしておく(ルーターの DHCP 予約など) |
| SRT の受付ポート | `8890` | 受信機の `mediamtx.srt_listen`(既定 `:8890`) |
| パス名 | `nc` | 受信機の `input.path`(既定 `nc`)。送信の鍵は `publish:nc`、受信側は内部で `read:nc` |
| 画面サイズ | 1024×576 | 受信機の画面と同じ大きさ。下の「解像度の決め方」 |

## 1. 配信(送信先)

**設定 → 配信**

| 項目 | 値 |
| --- | --- |
| サービス | **カスタム...** |
| サーバー | `srt://192.168.20.15:8890?mode=caller&latency=6000000&timeout=15000000` |
| ストリームキー | `publish:nc` |
| 認証を使用する | オフ |

サーバーの URL の意味(`?` のあとは `&` でつなぐ。空白を入れない):

| パラメータ | 値 | 意味 |
| --- | --- | --- |
| `mode=caller` | 固定 | OBS から受信機へつなぎにいく |
| `latency=6000000` | **6秒**(単位はマイクロ秒) | 受信側が、失った分の再送を待つ時間。**これが「何秒の断を映像に出さないか」を決める**。5秒の断を吸収するなら 6秒。代わりに映像は、常に約6秒遅れる |
| `timeout=15000000`(付けなくてもよい) | 15秒(単位はマイクロ秒) | **OBS では、SRT の無通信タイムアウトではない**(OBS の SRT 実装は、書き込みと接続の待ち時間の上限にだけ使う)。付けても、断への耐性は上がらない。SRT の無通信タイムアウト(libsrt の既定 **5秒**)は、OBS の URL からは変えられない |

ストリームキーは、OBS が SRT の `streamid` として渡す。`publish:` は MediaMTX の決まり(送信=publish、受信=read)、`nc` はパス名。

## 2. 出力(エンコーダ)

**設定 → 出力**。左上の「出力モード」を **詳細** にして、「配信」タブを開く。

| 項目 | 値 | 理由 |
| --- | --- | --- |
| 音声トラック | 1 | 受信機は音声を捨てる(使わない)。そのままでよい |
| 配信サービスの設定を適用 | オン(既定) | |
| エンコーダ | **x264**(ソフトウェア) | 実機で確かめたのは x264 だけ。NVENC や QSV を使うなら、キーフレーム間隔 1 秒とプロファイル main を指定できること(と、出力が H.264 であること)を確かめる |
| 出力のリスケール | オフ | 解像度は「映像」で決める |
| レート制御 | **CBR** | 一定の帯域にして、受信側の負荷と、ネットワークの揺れを小さくする |
| ビットレート | **4000** Kbps | Pi 3 の限界は 6000 前後。3000〜4000 が安全 |
| キーフレーム間隔 | **1** 秒 | **受信機は、次のキーフレームまで映像を出せない**。長い(0=自動は約8秒)と、起動・再接続のたびに、映像が出るまで最大8秒待たされる。1〜2秒にする |
| CPU 使用のプリセット | veryfast | |
| プロファイル | **main** | Pi 3 のハードウェアデコーダは、High に弱い場合がある。baseline でもよい |
| チューニング | **zerolatency** | エンコーダの内部遅延を無くす |
| x264 オプション | 空欄 | |

## 3. 映像(解像度と FPS)

**設定 → 映像**

| 項目 | 値 | 備考 |
| --- | --- | --- |
| 基本(キャンバス)解像度 | 1280×720 でも 1920×1080 でもよい | 画面を作る大きさ。シーンの素材に合わせる |
| 出力(スケーリング)解像度 | **1024×576** | **受信機の出力解像度と同じにする**(下の「解像度の決め方」) |
| ダウンスケールフィルタ | バイキュービック | |
| FPS の値 | **30** | 共通 FPS 値で 30 |

### 解像度の決め方

受信機は、送られた映像を、設定の `video.width × video.height` に ffmpeg で縮め・色変換して、画面へ書く。
**送る解像度と、受信機の解像度が違うと、受信機が縮小を行って、Pi 3 では CPU が足りず、コマ落ちする。**
そろえれば、縮小は行われない。実測(Pi 3B+、4Mbps、30fps):

| 解像度 | 受信 FPS |
| --- | --- |
| 1280×720(コンソールではなくデスクトップ起動) | 9〜10 |
| 1280×720(コンソール起動、`/dev/fb0` 直描画) | 19〜24 |
| **1024×576**(同) | **28〜35(30 に張り付く)** |

16:9 の画面なら、1024×576、または 848×480 など。決めた値を、**OBS と受信機の両方**へ入れる(受信機側は [`RASPBERRY_PI.md`](RASPBERRY_PI.md))。

## 4. 自動再接続(必須)

**設定 → 詳細設定**、「ネットワーク」の欄。

| 項目 | 値 | 理由 |
| --- | --- | --- |
| 配信が切れたら自動的に再接続する | **オン** | 受信機の再起動や、長い断で接続が切れたとき、人手なしに戻す |
| 再試行の遅延 | 2 秒 | |
| 最大再試行回数 | **大きく**(既定の 25 回だと、約1分で諦める) | 受信機が先に落ちていても、起動したら繋がるように |
| 新しいネットワークコードを有効にする | オフ | |
| 低遅延モード | オフ | |
| ビットレートに合わせて動的に変える | オフ | CBR を保つ |

## 5. つなぐ

1. 受信機(Pi)で `srtrx-run` を起動する(受信機を先でも後でもよい。OBS は再接続する)。
2. OBS 右下の **配信開始** を押す。
3. Pi の画面に映像が出る。ブラウザで `http://192.168.20.15:8088/?token=nc` を開くと、状態画面に、接続、FPS、ロス、RTT が出る。

OBS を、起動と同時に配信させるなら、ショートカットの起動オプションに `--startstreaming` を付ける。

### 設定が効いているかの確認

受信機で(`ssh pi@…`):

```bash
curl -s localhost:9998/metrics | grep ms_receive_tsb_pd_delay
```

`publish` の行が **`6000`**(ミリ秒)なら、`latency=6000000` が効いている。`120` など小さい値なら、サーバーの URL の `latency` が反映されていない(`?` と `&` と綴りを確かめる)。

## 6. 5秒の断を吸収できているか(試験)

受信機側で、OBS との通信だけを5秒止める(リンクは落とさない)。OBS のアドレスを `192.168.20.12` とする。

```bash
OBS=192.168.20.12
echo 1 | sudo tee /proc/sys/net/ipv4/conf/all/rp_filter /proc/sys/net/ipv4/conf/eth0/rp_filter
sudo ip route add blackhole $OBS/32; sleep 5; sudo ip route del blackhole $OBS/32
echo 0 | sudo tee /proc/sys/net/ipv4/conf/all/rp_filter /proc/sys/net/ipv4/conf/eth0/rp_filter
```

試験は、1回ごとに20秒あけて繰り返し、各回で「断の最中と、断のあと20秒の、最大のフレーム経過時間」と「ffmpeg の再起動」を見る。
実機(Pi 3B+、OBS Studio 32.1.2 + libsrt 1.5.2、受信機は `input.latency_ms=1000`、`input.recv_buffer_bytes=33554432`)の結果:

| 断の長さ | 回数 | 映像が止まらなかった回 | 止まった回の内容 |
| --- | --- | --- | --- |
| 3秒 | 3 | **3 / 3**(最大 66ms) | - |
| 4秒 | 4 | **4 / 4**(最大 44ms、ffmpeg の再起動 0) | - |
| 5秒 | 4 | **3 / 4** | 断のあと約3.3秒止まり、ffmpeg が1回再起動(下の「限界」の2) |

**5秒の断は、確実には吸収できない。** 確実に吸収できるのは、約4秒まで。限界は2つある:

1. **OBS の SRT は、5秒(libsrt の既定)の無通信で接続が切れる。** OBS の URL からは、この値を変えられない(`timeout` は別物)。
   5秒前後の断では、OBS が接続を切って再接続し(OBS のログに `Connection was broken`、`Reconnecting in 2.00 seconds`)、映像は、再接続のあいだ、**3〜10秒以上止まる**ことがある。
   この PC の素の `ffmpeg.exe`(同じ URL)は、5秒の断を5回、すべて耐えた。OBS だけが弱い(OBS の libsrt の差と見ているが、原因は確定していない)。
2. **断のあと、溜まった映像が一気に流れ込み、Pi 内の ffmpeg←MediaMTX の SRT が、`SEQUENCE DISCREPANCY. BREAKING CONNECTION` で切れて、ffmpeg が再起動する**(約3秒止まる)。
   受信バッファを増やすと(`input.latency_ms=1000`、`input.recv_buffer_bytes=33554432`)、4秒では起きなくなったが、5秒では、まだ起きる。

断が6秒を超えれば、映像は必ず止まる。
`timeout=15000000` を付けない(既定)場合の比較は、していない。付けても付けなくても、上の2つの限界は変わらないと考えている。

## 7. うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| 映像が出ない、受信機の状態が「接続していない」 | アドレスとポートを確かめる。受信機のファイアウォールで UDP 8890 を許可する。ストリームキーが `publish:nc` か。受信機の `input.path` を変えているなら、`nc` をそれに合わせる |
| 配信は「接続済み」なのに、画面が出るまで数秒〜10秒かかる | キーフレーム間隔が長い。**1秒**にする |
| 映像がカクつく(コマ落ち) | 受信機の CPU 不足。OBS の出力解像度を、受信機の `video.width × height` と**同じ**にする。ビットレートを下げる(3000)。OBS の PC が Wi-Fi なら、有線にする(下) |
| 画が乱れる、ブロックノイズが出る | ネットワークのロス。ロスが多いと、受信機のロスの表示が増える。`latency` を長くしても、足りない分は取り戻せない。有線にする |
| 4〜5秒以上の断で、映像が3〜10秒止まる | OBS の SRT が、5秒の無通信で接続を切って再接続している(OBS のログに `Connection was broken`)。OBS の URL からは変えられない。断を短くする(有線にする、電波を良くする)。6の「限界」を参照 |
| 画面が約6秒遅れる | `latency=6000000` のため(仕様)。断を吸収する代わりの遅れ。遅れを減らすなら、`latency` を下げる(吸収できる断も短くなる) |

### 有線にする

Wi-Fi の送信機(OBS の PC)と有線の Pi の組み合わせでは、約10%のパケットロスが出た(再送で回復はするが、余裕を食う)。
**OBS の PC は、有線 LAN(Ethernet)につなぐ。**

## 受信機が Pi 3 でないとき

受信機が x86 の PC などで、画面が大きいなら、受信機の `video.width × height` を上げ、OBS の出力解像度も同じにする。
1080p30 でも、ハードウェア(VA-API、QSV)かソフトウェアのデコードで動く(`docs/VERIFY.md`)。ビットレートは 6000〜10000、キーフレーム間隔は 1〜2 秒、`latency` と `timeout` の考え方は同じ。

## OBS の設定ファイルを直接書く場合

プロファイルのフォルダ: `%APPDATA%\obs-studio\basic\profiles\<プロファイル名>\`。OBS を**終了してから**書き換える(起動中は、終了時に上書きされる)。

`service.json`(配信):

```json
{"type":"rtmp_custom","settings":{"server":"srt://192.168.20.15:8890?mode=caller&latency=6000000&timeout=15000000","use_auth":false,"bwtest":false,"key":"publish:nc"}}
```

`streamEncoder.json`(エンコーダ):

```json
{"bitrate":4000,"keyint_sec":1,"preset":"veryfast","profile":"main","tune":"zerolatency","rate_control":"CBR"}
```

`basic.ini` の `[Video]`: `OutputCX=1024`、`OutputCY=576`、`FPSCommon=30`。`[Output]` に `Mode=Advanced`、`Reconnect=true`、`RetryDelay=2`、`MaxRetries=<大きい値>`。
